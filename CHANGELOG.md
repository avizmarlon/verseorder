- The footer's "Updated" date is the date of the last commit that changed the watch order (`src/data/` and `src/components/timeline-data.ts`), read with `git log` in `next.config.ts` and exposed as `NEXT_PUBLIC_CONTENT_UPDATED`, instead of the hand-edited `lastReviewedDate` (removed from `watch-order.json`). The Markdown and PDF scripts use the same date, and the README no longer repeats it.

- Placement notes: 100 → 86. Removed 14 that only summarised the plot or explained an obvious spot; rewrote others to say why the title sits where it does and to match Marvel's Disney+ timeline (Thor: The Dark World before Iron Man 3, Loki S2 after The Marvels, the Holiday Special before Quantumania and Vol. 3, VisionQuest as its last title). - Copy and footer: the hero reads “112 titles across the Marvel multiverse”, “A Marvel watch order that mixes chronology with storytelling” and “Explore the watch order”; “Scroll to travel” is gone; the correction link reads “Think I got something wrong?”. The footer leads with “Made by Marlon, a Marvel fan, for Marvel fans.” (`.b-made`), followed by a small muted block (`.b-legal`) with the correction, source and MIT License links, the updated date, the not-affiliated notice (Marvel, Disney, Sony; titles, characters, cover art and trademarks) and the unchanged TMDB attribution. The tagline is now “A Marvel Multiverse Watch Order” (README, `package.json` description, JSON-LD `alternateName`, `watch-order.json` subtitle, Markdown and PDF scripts, GitHub repo description). The meta/OG/Twitter description is shortened to 121 characters and the JSON-LD description matches it. `watch-order.json` drops the unused `editorialStatus`/`editorialNotice` and renames the internal `verification` value `original-curation-unreviewed` to `original-placement-unreviewed`; the Markdown and PDF scripts group titles by the nine chapters from `timeline-data.ts` (`content/watch-order.md` regenerated). The unused `VerseOrderExperience.tsx` and the `motion` dependency it alone used are removed. The footer e2e checks the new text and that the page has no “curated”, “editorial”, “journey”, “lit” or “ultimate”.
- Progress: the HUD shows `n/112 watched` next to the ring (`n/112` on phones) and opens a small progress menu with the next unwatched title, Export progress and Import progress. Export downloads `verseorder-progress.json` (`{ app: "verseorder", version: 1, exportedAt, watched: [ids in watch order] }`); import accepts that file or the bare ID array, adds the IDs to the saved progress, skips unknown IDs and reports the counts; anything else is rejected with nothing changed. Watched circles get a tooltip, hover, press and focus states. A one-time hint (dismissal kept in `localStorage`) explains marking a title as watched. Progress wording is plain: `n of N watched` per chapter, “Up next”, “You’ve watched everything!”, “Pick up where you left off” (shown only once something is watched), replacing “lit”, “Every chapter lit”, “Continue at”, “Resume your journey” and “Find your next story”.
- Reword the After Endgame, Spider-Man Multiverse and Marvel Before the MCU chapter descriptions: no quality judgments, and each says why the block sits where it does.
- Mobile (≤760px) HUD: the chapter pips become a horizontally scrolling chip row with all nine names; the active chip is scrolled into view and marked `aria-current`. The bar collapses to the brand dot + chip row while scrolling down (more than 8px per frame, not while the search field has focus) and expands on scroll up or within 60px of the top: 182px → 64px on a 390x844 phone. - Give every one of the 112 timeline cards a TMDB backdrop banner (per-title focus point) and a self-hosted, muted, looping trailer preview (AV1 WebM + H.264 MP4, 768x320, no audio) served from `https://media.verseorder.watch/clips/`. The detail drawer keeps the click-to-load YouTube embed.
- Preload card media ahead of the viewport. The scroller is the IntersectionObserver root, so the margin applies. Only the start of the next few cards is fetched, nothing loads before the page settles, far cards release their sources, Save-Data is respected, and only one video decodes at a time. On touch, the timeline dot drives playback, held back during flings.
- Serve the clips from the R2 bucket `verseorder-media` through the custom domain `media.verseorder.watch` instead of a Pages Function. R2 answers byte ranges natively (206, `Accept-Ranges`, `Content-Range`), the Cloudflare edge caches the objects (one-year immutable `Cache-Control`), and the bucket CORS policy allows GET/HEAD with `Range` from verseorder.watch. The site is now fully static: `functions/clips` (which used Worker CPU per range request and went over the free-plan CPU limit) is removed, the clips are left out of the Pages deploy, and CSP `media-src` allows the media host. Add `scripts/media/upload_clips.mjs` (MD5-diffed uploads) and the `mediaBase` setting in `site.config.json` (`NEXT_PUBLIC_MEDIA_BASE` overrides it).
- `scripts/media/upload_clips.mjs` no longer overwrites an R2 object whose ETag differs from the local MD5 (the one-year immutable cache would keep serving the old clip). It uploads nothing and exits 1, also with `--dry-run`, and asks for a new versioned file name. `--overwrite` forces it and purges those URLs from the Cloudflare cache. The decision logic is in `scripts/media/upload_plan.mjs`, covered by `npm run test:scripts` (`node --test`, run in CI).
- WebM clips are muxed with cues at the front so the first range request is enough to start playback.
- Add `scripts/media/build_media.py` + `scripts/media/manifest.json`: a TMDB lookup (official videos, textless backdrops, posters), fetch, rating-card/black trim, letterbox detection, encode and data apply.
